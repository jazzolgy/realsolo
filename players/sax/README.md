# Sax Player

AI Saxophonist workstream.

## Owns

- monophonic melodic realization
- phrase entrance / ending / breath / space
- register trajectory and leap grammar
- articulation: tongue, legato, accent, ghost, scoop, fall, doit, subtone
- bend / vibrato / growl / altissimo semantics
- rhythmic placement and microtiming
- motif development and call / response
- sax-specific physical feasibility
- saxophone-specific realization of shared style / LegendProfile evidence
- score-context interpretation for sax phrase and interaction policy

## Consumes from Shared Core

- Expected / Observed / Inferred Harmony
- Shared Scale & Linear Connection Intelligence
- Harmonic Reasoning Orchestrator and HarmonicActionOptions
- function / modal / local-key hypotheses
- contextual tension
- voice-leading / resolution debt
- form / phrase / narrative / memory
- ScoreContextSnapshot from the nine shared scorebooks
- ensemble state and interaction
- future-harmony awareness
- LegendProfileView / VocabularyQuery

The sax layer does not own a separate jazz-harmony theory and does not own
Charlie Parker data. It realizes shared harmonic/legend/score intelligence as a
monophonic saxophone action.

## Score rule

Written melody/solo/part evidence is authoritative for activity mode. If the
score says written material is active but the current written note is not
available, Sax does not invent a substitute note. Page-level or otherwise
unlocated feel/phrase evidence remains unresolved.

## Runtime contract

Slow Brain may plan intention, target family, contour, register, density and
active vocabulary memory. It must not prewrite a future solo.

Shared context -> immediate candidates -> commit ONE sax event -> listen ->
update score/harmony/ensemble/memory state -> re-plan.
