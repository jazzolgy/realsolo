# Harmonic Continuity → Pattern Consistency Policy v0.1\n\n## Purpose\n\nAutomatically estimate whether the current accompaniment should preserve a local\ncomping pattern or allow stronger variation.\n\nThis policy was motivated by cross-source study and selected transcription evidence:\n\n- Gibraltar: recurring Gm–C7 cycles sustain recognizable comping identity even\n  though the chord changes frequently.\n- Little Sunflower: static/modal harmony can still support changing texture.\n- Crisis: faster-moving harmony and formal change are associated with more frequent\n  texture/gesture change.\n\nTherefore raw chord-change rate alone is insufficient.\n\n## Input\n\nShared Core HarmonicFrame fields are observed without rebuilding harmony theory:\n\n- expected / observed / inferred harmonic evidence\n- next_expected\n- phrase_position\n- cadence_state\n\nThe piano layer stores only a short recent history of harmonic fingerprints:\n\n- root pitch class\n- symbol\n- function\n- local key\n\nNo exact future note or voicing sequence is stored.\n\n## Features\n\n### hold_stability\n\nMeasures how long the current harmonic identity has remained unchanged.\n\nUseful for static/modal fields, pedals, and long-duration harmony.\n\n### change_rate\n\nMeasures raw harmonic identity changes across recent frames.\n\nImportant, but not sufficient by itself.\n\n### recurrence_strength\n\nDetects short repeated cycles of length 1–4.\n\nThis is essential for vamp behavior:\n\nGm7 → C7 → Gm7 → C7\n\nwhich has a high raw change rate but also high recurrence.\n\n### boundary_pressure\n\nUses late phrase position, non-open cadence state, and known imminent harmonic change\nto reduce pattern persistence near likely resets.\n\n## Pattern consistency estimate\n\nThe current heuristic rewards static hold, rewards recurring harmonic cycles,\npenalizes non-recurring rapid change, and lowers consistency near phrase/cadence\nboundaries.\n\nHigh harmonic recurrence can therefore offset high raw chord-change rate.\n\n## Runtime contract\n\nperform_one_comping_action with a HarmonicFrame:\n\n1. observes the current harmonic frame;\n2. updates bounded harmonic-continuity memory;\n3. estimates current pattern consistency;\n4. uses that value only to bias the current candidate evaluation;\n5. commits one immediate gesture;\n6. listens/re-plans.\n\nNo future rhythmic pattern is scheduled.\n\n## Manual override\n\nFor experiments/ablation:\n\n- auto_pattern_consistency=True uses the harmonic/form-derived value when available;\n- auto_pattern_consistency=False uses the manually supplied pattern_consistency_strength.\n\nThis makes controlled comparisons possible.\n\n## Important interpretation\n\nPattern consistency is not the same as literal repetition.\n\nA high-consistency context may preserve rhythmic placement identity, role identity,\nor family identity while varying exact voicing, register, dynamics, touch, attack\nomission, or response timing.\n\nThe goal is local continuity, not copying.\n\n## Status\n\nDESIGN-INFERENCE grounded by transcription comparison.\n\nThe exact weights, history length, recurrence window, and boundary thresholds remain\nexperimental and should be calibrated later using larger transcription/audio sets and\nexpert review.
